Expanded CPU test coverage, 2026-10-17
====================================

CPU base: e013d2e6a896a817bcdc7f3aad5d5e39ecb2b4d6 (PR #2 master), plus the narrow
MOVE/MOVEA legality and synchronous ILLEGAL exception fix in this PR. Invalid
forms previously read outside the cycle table, producing process-dependent timing.
The fix raises vector 4 with the fault PC, saved SR and 34 cycles. Other opcode
implementations are unchanged. Linux x86-64, GCC 14.2, Debug, Python 3.13.
Sources, scope, masks and runnable commands are documented in COMPLETE.txt.

All 84 original instruction groups have real specifications. The 67 unasserted
C++ templates are replaced, while 17 asserted original groups remain as an extra
regression layer. The expanded suite contains 8,089 instruction cases and 40
sequence cases. It exercises all shift counts and X states, CCR conditions,
immediate bit numbers, effective address modes and control/exception sequences.

The full eight-pattern command defines 532,417 cases per decoder (1,064,834
evaluations across both), including readable specifications. The corrected local
full audit report is under build/complete-cpu-corrected/report.json; use the
commands in COMPLETE.txt to reproduce it. The quick CI run covers every opcode
word with one fixed pattern, and reports all remaining failures explicitly.

After the legality/exception correction, all readable and quick-sweep expected
outputs had the exact same digest as before it. The reviewed snapshots only
removed resolved wrong bits: zero new wrong-bit cases were accepted. In
particular, nondeterministic invalid-MOVE cycles were fixed at their source,
not accepted by broadening timing masks or disabling illegal-word assertions.

The differential expectations come from pinned Musashi, checked against every
readable specification with exactly three documented independent-reference
disagreements. Correct manual expectations are retained. The unreliable external
TAS/TRAPV data remains quarantined in the MAME layer, but both operations now have
active readable and complete-decode tests, including both TRAPV outcomes.

Expanded readable cases with ASan/UBSan, PER decoder:

Executed                                      8,129
Passed all checked assertions                  5,671
Failed an assertion                              914
Crashed/stopped on undefined behavior           1,544

These are failing CPU cases, not 1,544 distinct source bugs. Examples include
signed 32-bit addition/subtraction overflow, shift exponents >=32, and signed
division INT_MIN/-1. Crashes remain failures with diagnostics. Infrastructure and
known-failure regression gates passing do not certify CPU correctness or safety.

Z80: every downloaded case was hash checked and schema validated: 1,604 groups,
1,604,000 cases, including base/CB/ED/DD/FD/indexed-CB forms. Execution remains
BLOCKED for all those cases because DrivOnix has no Z80 CPU backend. The runner
and worker contract check registers/flags/internal state, RAM, ports, cycle totals
and optional bus-pin traces; an absent backend can never produce a strict pass.

The independent MAME layer from BASELINE.txt remains available: 312,500 active
external cases plus the original 28 examples through each decoder, with 5,000
unreliable external TAS/TRAPV cases explicitly quarantined per decoder.

Every opcode word having cases does not mean all operand values, bus pins, wait
states, fault combinations or console behavior have been verified. Remaining
interface boundaries are listed in COMPLETE.txt. These counts are not an emulator
accuracy percentage; state/timing coverage and case distributions differ.
