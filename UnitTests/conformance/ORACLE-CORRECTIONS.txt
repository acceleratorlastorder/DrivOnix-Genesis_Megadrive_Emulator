Independent MC68000 oracle corrections
======================================

Pinned Musashi source remains byte-for-byte verified and test-only. Its wrapper
corrects the following specific discrepancies rather than weakening assertions
or changing the production CPU to reproduce inaccurate reference behavior.

68000 arithmetic timings (referenceAdapter.cpp)
-----------------------------------------------

Motorola's M68000 User Manual instruction timing tables and the independently
pinned MAME corpus agree on these exact instruction classes:

* ADD/SUB.L Dn or An,Dn: 8 cycles; Musashi's table reports 6.
* ADDA/SUBA.L Dn or An,An: 8 cycles; Musashi's table reports 6.
* AND/OR.L Dn,Dn: 8 cycles; Musashi's table reports 6.
* ADD/SUB/AND/OR.B/W #immediate,Dn (EA immediate encoding): 8 cycles;
  Musashi reports 10. These are distinct from ADDI/SUBI/ANDI/ORI opcodes.
* ADDA/SUBA.W #immediate,An: 12 cycles; Musashi reports 14.
* ADDQ.W #n,An: 8 cycles; Musashi reports 4. SUBQ.W is already correct.
* ANDI.L #immediate,Dn: 16 cycles; Musashi reports 14 (MAME AND.l #771,0283).
* BCHG/BSET register destinations take 6/8 dynamic cycles or 10/12 immediate
  cycles for bit indices 0..15 / 16..31. BCLR takes 8/10 or 12/14 respectively.
  Musashi always uses the slower count. Memory destinations are unchanged.
* Dynamic BTST with an immediate EA takes 10 cycles; Musashi reports 8.

The wrapper applies these adjustments only to those opcode classes. Memory-EA
operations, illegal encodings, and other CPU families retain their oracle totals.
Readable timing_cases() independently assert the exact totals, result state,
and flag preservation, including SUBQ.W as a guard against overbroad correction.
MAME examples include ADD.l #014 (d886), ADDA.l #008 (dfcd), AND.l #012 (ce81),
ADD.b #076 (dc3c), ADD.w #251 (d67c), and ADDA.w #160 (defc).

MOVE16 CPU-model guard (referenceBridge.c)
-----------------------------------------

The pinned oracle accidentally executes 68040 MOVE16 encodings f620..f627 on a
68000. The bridge delivers the MC68000 line-F exception with the fault PC and 34
cycles. Eight explicit readable specifications independently assert this behavior.

The existing three documented divide-state disagreements remain recorded in
reference-limitations.json. MUL/DIV oracle timing is still unsuitable for
operand-dependent timing checks; independent MAME vectors assert those totals.

MAME vectors also represent single-instruction semantics, with boundary trace
service outside that operation. The explicit worker profile suppresses only the
subsequent trace boundary for those vectors; normal emulator execution and the
readable multi-instruction tracing tests continue to service trace exceptions.

Invalid BCD correction-network inputs (referenceAdapter.cpp)
---------------------------------------------------------

Pinned Musashi's decimal comparisons disagree with the independent MAME
microcoded core on non-BCD source bytes. The wrapper captures the original
operands and applies the MC68000 correction network to the resulting byte and
defined C/X/sticky-Z flags. It does not alter the undefined N/V comparison masks.
All 2,500 ABCD, 2,500 SBCD, and 2,500 NBCD MAME input/output pairs independently
confirm the network, including same-register predecrement ordering. NBCD uses
the subtract network with a zero destination. Exact readable cases assert:

* ABCD 5D + 36 + X -> 9A, C=X=0 (not FA with carry).
* SBCD DA - 01 -> D9, C=X=0 (not 79 with carry).
* SBCD 10 - 0F - X -> FA, C=X=1 (decimal borrow without binary high correction).
* NBCD FF with X -> 9A, C=X=1 (not an unchanged FF with carry cleared).

Production arithmetic remains independent of the oracle adapter; no tested CPU
outputs, alternate expected values, or baselines are used by the wrapper.

Address faults and instruction-pipeline staging
-----------------------------------------------

Pinned Musashi uses a flat 50-cycle operand address error and permits some
odd control-flow targets to survive until the next instruction fetch. Independent
MAME bus sequences distinguish the already performed EA/prefetch work. The
reference wrapper corrects exact fault-stage totals and saved-PC fields; it does
not disable cycle, RAM, flags, or register comparisons.

For an ordinary operand read, register indirect/postincrement starts at 58
cycles; predecrement adds 2, displacement/absolute-word adds 4, indexed adds 6,
and absolute-long adds 8. Previously consumed immediate words add 4 each. Saved
PC depends on the extension-fetch stage. MOVE writes additionally account for
the source transfer and the destination's actual write stage. Long predecrement
writes try the low word first; MOVE-specific flags, An commit, and IR latching
are retained at the observed fault boundary. These cases are separately checked
by the independent, unchanged MAME corpus; all 10,000 MUL/DIV vectors pass both
production decoders including these faults and operand-dependent cycle totals.

For MOVE.L write faults, direct data/address-register and immediate sources
retain the complete previous flags when writing (An)/(An)+, and retain previous
C/V with displacement/index destinations. Immediate EA is a direct source for
this rule. Memory sources have their separate low-word-N staging. Independent
MAME examples include MOVE.l #058 (D7 to indexed, SR211A to SR2112 preserving V),
#176 (A1 to displacement preserving C/V), and #063 (immediate to (A3)+ retaining
the complete previous flags). Four exact readable guards cover these paths;
all 3,050 MOVE.L encodings also match across eight deterministic input patterns.

An odd taken Bcc/DBcc target faults during that instruction (60 cycles); BSR
uses 68, RTS 66, and RTE/RTR 70. For JMP/JSR the precise target-fetch totals are
58 for (An), 60 for displacement/absolute-word/PC-displacement, 64 for indexed,
and 62 for absolute-long addressing. These overlap extension processing and
cannot be obtained by adding generic operand-EA timing. The reference bridge
invokes the pinned core's own address-error frame machinery. JSR target-fetch
ordering and DBcc counter commit are restored to the documented fault stage
before invoking that independent exception machinery. No production CPU outputs
are supplied to the reference.

Divide-zero and CLR dummy-read faults
-----------------------------------

The DIV divide-zero path clears C before stacking SR; the wrapper corrects both
live SR and the saved SR, not merely the visible final flag. Two new explicit
readable cases seed C=1 to assert this behavior (undefined N/Z/V remain masked).

A 68000 memory CLR first performs a dummy read. Pinned Musashi directly writes
zero and thus faults too late, with write-direction SSW and modified flags.
The fixture restores the read-direction SSW and original flags for an odd CLR
operand; exact word/long readable cases check the 62-cycle absolute-word path,
seven-word frame, saved PC, and unchanged pre-instruction flags.

Control-instruction reference discrepancies
------------------------------------------

MOVE SR,<ea> also performs a word dummy read on the original 68000. Pinned
Musashi writes directly, producing a write-direction address-fault frame and
the wrong saved-PC stage for this encoding. The adapter restores the read bit
and applies the word-sized read-stage PC rules. Four independent readable
cases cover indirect, postincrement, predecrement, and absolute-word faults;
all 2,500 unchanged MAME MOVE-from-SR cases pass through both decoders.

LINK A7 must push the original A7 value. Pinned Musashi captures A7 after the
four-byte push decrement, storing original A7-4 instead. The test wrapper
restores only that pushed original value, retaining any overlapping subsequent
trace frame. An explicit readable case and all 2,500 unchanged MAME LINK cases
independently assert the original-A7 behavior.

CHK's two signed trap paths have different timing: the upper-bound comparison
uses 38 cycles plus operand-access work; the subsequent negative-value path
uses 40 plus that work. Pinned Musashi discards the EA work and reports one
40-cycle trap path. The adapter captures the bound before executing the pinned
core, determines the corresponding signed check, and corrects only trap timing.
Three readable cases cover register/immediate/indirect bounds. CHK C/V/Z are
architecturally undefined and remain excluded in both live and stacked SR;
the defined trap N bit, other flags, exception frame, and cycles are checked.

Validation and limits
---------------------

The complete unchanged active MAME corpus contains 125 groups of 2,500 cases.
It passes 625,056 evaluations across both production decoders, including 28
handwritten cases per decoder. Fifty evaluations have no upstream cycle total;
all remaining evaluations compare cycles as well as defined CPU and RAM state.
TAS/TRAPV upstream groups remain explicitly quarantined for the previously
documented upstream data issues, with separate readable production tests.
This corpus checks instruction semantics, not full-machine compatibility,
bus-error recovery, or exhaustive combinations of multi-instruction prefetch.
