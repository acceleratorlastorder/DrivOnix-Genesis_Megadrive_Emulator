DrivOnix settings
================

The frontend and this INI file use the same typed settings, validation and save
code. INI is ordinary UTF-8 text with named sections and key/value pairs. Edit
it while DrivOnix is closed, or use the frontend settings and remapping screens.
Manual file edits are read on the next launch.

Finding the active file
----------------------

  drivonix --print-config-path

Default writable locations:

  Linux:   $XDG_CONFIG_HOME/drivonix/drivonix.ini
           or $HOME/.config/drivonix/drivonix.ini
  Windows: %LOCALAPPDATA%/drivonix/drivonix.ini

Relative XDG_CONFIG_HOME values are ignored. Application-owned path components
are lowercase; existing system/user directory names retain their real spelling.
Printing the path never creates files or opens a window. Missing parent folders
are created automatically. If no usable profile root exists, use --config or
--portable:

  drivonix --config /my/settings/drivonix.ini game.bin
  drivonix --portable game.zip

--config selects an explicit file, resolving relative paths against the startup
working directory. --portable uses config/drivonix.ini beside the executable
(bin/config/drivonix.ini in an extracted release). They cannot be combined.
Installed share/drivonix/config/drivonix.ini is a reference template.

Display, audio and interface
----------------------------

  [display]
  scale=1
  integer_fit=true
  fullscreen=false

  [audio]
  enabled=true
  volume=100

  [interface]
  show_bios=false
  window_width=1280
  window_height=720

  [metadata]
  online=true

scale remains the explicit integer game scale (1..8). integer_fit fits the game
using whole pixels; disable it to use the explicit scale. New profiles default
to a 1280x720 window. Older files containing display.scale but no integer_fit or
interface.window_width retain fixed scaling and get a compatible window size.
The interface window dimensions must be within 640x360 and 7680x4320.

show_bios opts into the existing boot sequence. Online metadata may be disabled
without disabling local games. volume is host playback gain (0..100), and disabling
host audio leaves emulated sound-chip execution active. --no-audio is a temporary
override and is never written to the INI.

Library folders
---------------

  [library.games]
  path="/home/me/games"
  enabled=true
  recursive=true

Each library.<id> section represents one folder. Stable ids contain 1..64
lowercase letters, numbers, hyphens or underscores; ids must be unique. The
frontend creates ids when adding folders. Disabling a folder retains its path.
recursive controls scanning subfolders. Up to 256 roots can be configured.
Paths are UTF-8 and may contain spaces, semicolons and hashes when quoted.
Windows examples can use forward slashes: path="D:/games". In a quoted value,
write a literal backslash as \\ and a literal quote as \". Unquoted Windows
paths retain their backslashes, but ; and # begin comments.

Keyboard and controller mappings
--------------------------------

  [input]
  enabled=true
  deadzone=25
  player1=0
  player2=1

input.enabled controls physical game input; the keyboard and frontend navigation
remain available. Native controller indices are Windows 0..3 or Linux 0..7; -1
disables a player port. Windows indices 4..7 are accepted but disconnected. The
left-stick deadzone is 1..95 percent. Xbox controllers use system XInput on
Windows and the existing CSFML joystick backend on Linux.

Each player has independent keyboard.player1/controller.player1 sections (and
player2 equivalents). The keys are up/down/left/right/a/b/c/start/x/y/z/mode:

  [keyboard.player1]
  up="w"
  a="k"

  [controller.player1]
  up="dpad_up,left_y+"
  a="x"
  b="a"
  c="b"

Binding values are symbolic names, comma-separated alternatives, or "none".
Keyboard symbols include letters, num0..num9, arrows, enter, space, lcontrol,
lshift, numpad0..numpad9 and f2..f15 (except reserved f11). The default player-one
keyboard controls preserve Z/S/Q/D movement and K/L/M for A/B/C. Player two uses
arrows and the numeric keypad. The reference template lists every binding.

Controller symbols include a/b/x/y, lb/rb, back/start, l3, dpad_up/down/left/right,
left_x+/left_x-/left_y+/left_y-, right_x+/right_x-/right_y+/right_y-, left_trigger,
and right_trigger. Positive Y means up. Additional Linux buttons can use
button_0..button_31; normalized axes use axis_0+..axis_7- (left X/Y, triggers,
right X/Y, D-pad X/Y). Other Linux hardware layouts may differ.

Default Xbox X/A/B map to Mega Drive A/B/C; Y/LB/RB map to X/Y/Z; Menu/Start is
Start and View/Back is Mode. Both D-pad and left stick move. Escape/F1 and R3
(right-stick click) are reserved menu controls; F11 toggles fullscreen. Those
keys and R3/button_10 cannot be assigned to game actions. UI navigation uses
arrows/D-pad/stick, Enter/Xbox A to confirm and Escape/Xbox B to go back, regardless
of game remapping.

Remapping waits for existing input to be released, then captures a fresh key,
button or deliberate axis movement. Conflicts require a swap or cancellation;
disconnection cancels capture. Returning to a game waits for neutral input so
menu confirmation cannot become an accidental game press. Input releases on
focus loss or disconnection; keyboard and controller holds remain independent.

Validation and saving
---------------------

Known sections/keys and binding names are case-insensitive. Booleans accept
true/false, yes/no, on/off or 1/0. UTF-8 BOM and CRLF/LF text are supported.
Double-quoted values support \\, \", \n, \r and \t escapes. Unknown keys and
sections, comments and unchanged formatting are preserved on save. Removing a
library folder removes its active fields while keeping unrelated comments and
unknown data. Existing files do not gain every new default unless those settings
are explicitly changed; missing options still receive current defaults in memory.

Duplicate known options, malformed syntax, invalid values and reserved game
bindings produce path/line/key errors and leave the file unchanged. Saves use
unique temporary files, flush and atomic replacement. Changes made on disk since
loading are detected instead of silently overwritten. Failed writes keep the
previous file and pending in-memory settings for retry. Directory-sync errors
can happen after replacement; the document records the new baseline so retry
remains meaningful.

A missing default/portable INI may import ScreenSize=1/2/3 from legacy
Config/config.txt or config/config.txt once, retaining the old file. An existing
INI always wins; an unreadable or invalid file is never treated as missing.

All tracked source/runtime/package paths are lowercase except CMake's required
CMakeLists.txt. Upstream URLs, SDK includes and external archive members keep
their original spelling.
