CPU validation coverage, 2026-10-31
=================================

The original DrivOnix 68000 core is repaired in place. An optional independently
pinned Musashi worker supplies differential expectations only; it is never linked
into the emulator. Both production and legacy decode paths are exercised. Correct
hardware expectations are preserved; CTest/CI no longer accept known failures
through baseline arguments. Historical snapshots remain available as audit history.

External TAS/TRAPV data has 5,000 unreliable cases per decoder, explicitly
excluded and reported by --active-only, never counted as passing. Readable cases
and the all-word sweep independently execute those instructions. The comparison
checks state, address-fault frames and supplied cycle totals, including
operand-dependent MUL/DIV timing. Undefined flags/SSW bits are masked within their
hardware scope. The CHK mask was tightened to assert live N on a taken bounds
trap as well as saved N; all 5,000 CHK evaluations were rerun and passed after
that change, with other groups unchanged. Successful CHK retains undefined NZVC.
Adapter corruption guards detect wrong live/saved trap N while permitting only
undefined C/V/Z changes. See readme.txt for masks and execution profiles.

The full strict run completed all eight patterns on both decoders, including
all reserved/illegal words and all readable specifications. It used independent
expected outputs, with the bounded reference corrections documented in
oracle-corrections.txt. The strict --quick command uses one pattern plus all
readables: 147,466 evaluations across both decoders. See complete.txt for commands.

The latest readable cases add precise guards for dummy-read address faults in
CLR and MOVE SR, LINK A7 capture order, CHK trap timing and odd JMP/JSR targets.
Four additional MOVE.L fault guards distinguish retained C/V and immediate-source
flags at the failed write boundary. Sequences observe next-instruction prefetch
after writes through absolute-word and absolute-long destination extensions. They complement the original
source/destination/flags/addressing tests and broad independent random vectors.

The optional oracle is itself validated against the readable cases. Three exact
pre-existing divide-state discrepancies are retained in reference-limitations.json;
all other changes fail closed for review. oracle-corrections.txt documents precise
reference defects and hardware evidence. MUL/DIV differential timing is omitted
because that oracle uses unsuitable fixed counts; MAME checks their timing.

The production Z80 backend strictly executed all 1,604,000 pinned cases across
1,604 base/prefix groups: 1,604,000 passes and zero failures. Its core wrapper is
shared by production and z80_worker. Comparison includes documented/undocumented
state, RAM, I/O transactions and total T-states. It does not emit pin traces.
See ../../z80/readme.txt and complete.txt for commands and integration scope.

Sanitizer policy and hardware limits
-----------------------------------

The final readable suite also passed strictly with ASan/UBSan: 16,394 executed,
16,394 passed and zero failures/crashes. The three original opcode/legacy CTest
targets passed in that sanitizer build as well. All seven CPU CTest targets use
strict acceptance; old unsafe-case baselines do not exempt failures. These
observations cover the executed cases, not every possible production input.

Opcode coverage is not exhaustive operand coverage or an emulator accuracy
percentage. Electrical pins, byte strobes, wait states, arbitration, externally
injected bus errors/double-fault halt, vectored/spurious interrupt acknowledge and
the final internal prefetch queue remain outside these CPU fixtures. Separate
console tests exercise hardware integration. Diagnostic ROM boot/render/input
and CPU vector success do not establish complete commercial-game compatibility
or measured real-game performance.
